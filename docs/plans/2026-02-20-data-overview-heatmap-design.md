# Data Overview Heatmap Report

## Summary

A multi-year GitHub-contributions-style heatmap showing all data in chronological order.
Each cell is a day, colored by average glucose. Hovering shows a tooltip with counts; clicking
opens a detail panel with per-data-type breakdown. Filterable by data source. Lazy-loaded per year.

## Backend

### New Controller: `DataOverviewController` (`/api/v4/data-overview/`)

#### `GET /api/v4/data-overview/years`

Returns the range of years that contain data. Used by the frontend to know the scroll bounds.

**Response:**
```json
{
  "years": [2023, 2024, 2025],
  "availableDataSources": ["dexcom-connector", "glooko-connector", "manual"]
}
```

**Implementation:** `SELECT DISTINCT EXTRACT(YEAR FROM to_timestamp(mills / 1000.0))` across
all relevant tables (sensor_glucose, meter_glucose, boluses, carb_intakes, bolus_calculations,
notes, device_events, state_spans, entries, treatments, activities, foods, device_statuses).
Union the results, sort descending.

For `availableDataSources`: `SELECT DISTINCT data_source` across the same tables, filtered to non-null.

#### `GET /api/v4/data-overview/daily-summary?year=2025&dataSource=glooko-connector`

Returns day-level aggregated counts and average glucose for one year.

**Parameters:**
- `year` (int, required) - The year to aggregate
- `dataSource` (string?, optional) - Filter to a specific data source

**Response:**
```json
{
  "year": 2025,
  "dataSource": null,
  "days": [
    {
      "date": "2025-10-20",
      "averageGlucoseMgdl": 145.2,
      "totalCount": 312,
      "counts": {
        "Glucose": 288,
        "ManualBG": 0,
        "Boluses": 8,
        "CarbIntake": 4,
        "BolusCalculations": 4,
        "Notes": 1,
        "DeviceEvents": 3,
        "StateSpans": 4,
        "Profiles": 0,
        "DeviceStatus": 0,
        "Activity": 0,
        "Food": 0
      }
    }
  ]
}
```

Only days with at least one record are included (sparse array).

### New Service: `IDataOverviewService`

**Interface** in `Core.Contracts`:
```csharp
public interface IDataOverviewService
{
    Task<DataOverviewYearsResponse> GetAvailableYearsAsync(CancellationToken ct);
    Task<DailySummaryResponse> GetDailySummaryAsync(int year, string? dataSource, CancellationToken ct);
}
```

**Implementation** in `API/Services/DataOverviewService`:

The daily summary query strategy for each SyncDataType mapping:

| SyncDataType        | V4 Table              | Legacy Fallback        | Glucose? |
|---------------------|-----------------------|------------------------|----------|
| Glucose             | sensor_glucose        | entries (type=sgv)     | Yes      |
| ManualBG            | meter_glucose         | entries (type=mbg)     | Yes      |
| Boluses             | boluses               | treatments (bolus)     | No       |
| CarbIntake          | carb_intakes          | treatments (carbs)     | No       |
| BolusCalculations   | bolus_calculations    | -                      | No       |
| Notes               | notes                 | treatments (Note)      | No       |
| DeviceEvents        | device_events         | -                      | No       |
| StateSpans          | state_spans*          | -                      | No       |
| Profiles            | therapy_settings      | profiles               | No       |
| DeviceStatus        | pump/uploader snapshots| device_statuses       | No       |
| Activity            | -                     | activities             | No       |
| Food                | -                     | foods                  | No       |

*StateSpans use `start_mills` and `source` (not `data_source`/`mills`).

Each table query:
```sql
SELECT
  DATE(to_timestamp(mills / 1000.0)) AS day,
  COUNT(*) AS count
FROM {table}
WHERE mills >= {yearStartMillis} AND mills < {yearEndMillis}
  [AND data_source = {dataSource}]
GROUP BY day
```

Glucose average:
```sql
SELECT
  DATE(to_timestamp(mills / 1000.0)) AS day,
  AVG(mgdl) AS avg_glucose
FROM sensor_glucose
WHERE mills >= ... AND mills < ...
  [AND data_source = ...]
GROUP BY day
```

Results are merged in C# into the response DTO, keyed by date string.

## Frontend

### Route: `/reports/data-overview`

New page at `src/Web/packages/app/src/routes/reports/data-overview/+page.svelte`.

### Remote Functions: `data-overview.remote.ts`

```typescript
// Auto-generated by RemoteQuery attribute, plus hand-written wrapper:
export const getDataOverviewYears = query(async () => {
  const { locals } = getRequestEvent();
  return locals.apiClient.dataOverview_getAvailableYears();
});

export const getDailySummary = query(
  z.object({ year: z.number(), dataSource: z.string().optional() }),
  async ({ year, dataSource }) => {
    const { locals } = getRequestEvent();
    return locals.apiClient.dataOverview_getDailySummary(year, dataSource);
  }
);
```

### Color Scale

Uses glucose-clinical thresholds with CSS variables for theme consistency:

```typescript
cScale: scaleThreshold()
  .domain([54, 70, 180, 250])
  .range([
    'var(--glucose-very-low)',    // < 54
    'var(--glucose-low)',         // 54-70
    'var(--glucose-in-range)',    // 70-180
    'var(--glucose-high)',        // 180-250
    'var(--glucose-very-high)',   // > 250
  ])
  .unknown('hsl(var(--muted))'), // no glucose data
```

### Lazy Loading Strategy

1. On mount: call `getDataOverviewYears()` to get year list
2. Render current year immediately, call `getDailySummary(currentYear, dataSource)`
3. Render placeholder divs for each older year with height matching expected calendar height
4. `IntersectionObserver` watches placeholders; when visible, trigger `getDailySummary(year, dataSource)`
5. Replace placeholder with rendered Calendar when data arrives
6. When data source filter changes: clear all loaded data, re-fetch current year, re-observe others

### Navigation Interactions

| Interaction | Target |
|-------------|--------|
| Click month label (e.g. "Mar") | `/calendar?year=YYYY&month=MM` |
| Click week area (row of 7 cells) | `/reports/week-to-week?date=YYYY-MM-DD` (Monday of that week) |
| Click individual cell | Opens DayDetailPanel with that day's data |
| Detail panel "Day in Review" button | `/reports/day-in-review?date=YYYY-MM-DD` |

### Detail Panel

- Slides in from the right (or occupies a fixed right column on desktop)
- Shows: date, average glucose (formatted per user preference), and a list of all 12 SyncDataType counts
- Uses `getDataTypeLabel()` from `data-type-labels.ts` for display names
- Only shows data types with count > 0 (collapsed, with option to show all)
- Includes a prominent "View Day in Review" link/button
